# MetricPulseAI Agentic Architecture

MetricPulseAI is an agentic KPI analytics assistant for CSV business data.

## Main Idea

The LLM does not calculate metrics directly.

Instead:

LLM = plans and explains  
Python = calculates and verifies  

## High-Level Flow

User question
-> MetricPulse Analyst Agent
-> LLM planner creates JSON tool plan
-> JSON parser validates the plan
-> Plan runner executes the tools
-> Python tools calculate verified results
-> LLM explainer writes the final business answer

## Main Agent

The main agent is:

MetricPulse Analyst Agent

It reads the user question, chooses tools, runs the validated plan, and explains the results.

## Tools

The agent can use:

- profile_dataset
- calculate_kpi_trend
- compare_periods
- analyze_root_cause
- detect_anomalies
- forecast_kpi
- run_sql_query
- generate_insight_summary

Tool definitions are in:

src/tool_registry.py

Tool execution is in:

src/tool_executor.py

## LLM Planning Layer

The LLM planner receives:

- user question
- available tools
- dataset columns
- selected KPI
- available time periods

It returns a JSON plan of tool calls.

## Safety Layer

Before running the LLM plan, the app validates it in:

src/llm_plan_parser.py

It checks:

- valid JSON
- allowed tool names
- real column names
- safe arguments

## Plan Runner

Validated plans are executed by:

src/llm_plan_runner.py

It records the tool trace.

## Final Explanation

The final answer is generated by:

src/llm_explainer.py

The explainer uses only verified Python outputs and is told not to invent numbers or causes.

## Why This Is Agentic

MetricPulseAI is agentic because the LLM-powered agent can:

- understand the user question
- choose tools dynamically
- call tools through a safe pipeline
- observe tool outputs
- produce a grounded final explanation
